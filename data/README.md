# Як читати дані

У папці — паспорти опитувань, формулювання питань, числові ряди та опубліковані перехресні розподіли. Це зведення відкритих результатів, а не відповіді окремих респондентів.

| Файл | Один рядок / запис | Обсяг |
|---|---|---|
| [polls.csv](polls.csv) | Паспорт хвилі, ретроспективної точки або агрегату хвиль | 119 записів |
| [questions.csv](questions.csv) | Питання, твердження, сценарій або батарея у конкретному опитуванні | 143 записів |
| [dynamics.csv](dynamics.csv) | Значення однієї категорії відповіді в одній хвилі часового ряду | 369 значень у 23 серіях |
| [crosses.csv](crosses.csv) | Частка відповіді серед зазначеної підгрупи | 118 значень |
| [research.json](research.json) | Реєстр із цими чотирма розділами, джерелами та довідковими матеріалами | 150 посилань на джерела |
| [wording.json](wording.json) | Формулювання з джерела та його зв’язки з питаннями і хвилями | 133 об’єктів формулювань |
| [more-charts.json](more-charts.json) | Дані графіків окремих питань і додаткові налаштування часових рядів | 160 панелей для 143 записів |

Обсяги наведено для версії після перевірки 06.10.2026. Для читання без широких CSV є [сайт](https://velgaks.github.io/peace-agreement-polls/); правила добору й порівняння опитувань — у [методології](../docs/METHODOLOGY.md).

## Загальні правила

- CSV мають кодування UTF-8 із BOM, роздільник — кома. Для імпорту в Excel оберіть ці параметри, якщо файл не розбився на колонки автоматично.
- `pct` у `dynamics.csv` та `crosses.csv` — **частка від 0 до 1**: `0.36` означає 36%. Натомість `value` у графіках `more-charts.json` з одиницею `percent` уже містить відсотки: `36` означає 36%.
- Порожня клітинка означає відсутність значення або незастосовність поля. Вона не дорівнює нулю. `[]` — порожній список доступних елементів, а не доказ відсутності варіантів відповіді в анкеті.
- Масиви й об’єкти всередині CSV записані як JSON. Це стосується, зокрема, `fieldwork_periods`, опцій і списків тверджень.
- `source` — ID у розділі `sources` файла `research.json`; `source_url` — готове посилання. Джерела чисел, формулювання та дат можуть бути різними.
- Назви й короткі перекази не замінюють тексту анкети. Рівень підтвердження формулювання та обмеження вказані окремо.

## polls.csv — паспорти опитувань

Один запис не завжди дорівнює незалежній вибірці: це може бути точка з ретроспективного графіка або середнє кількох хвиль. `id` — ключ для приєднання решти таблиць.

| Колонки | Зміст |
|---|---|
| `id` | ID запису, наприклад `P01` |
| `pollster`, `commissioner` | Виконавець і замовник / ініціатор |
| `title`, `topics` | Редакційна назва запису й теми |
| `priority` | Пріоритет джерела в добірці; не числова оцінка якості |
| `n` | Загальна чисельність вибірки, коли встановлена. База окремого питання може бути меншою |
| `method`, `population` | Метод опитування та населення, яке охоплює вибірка |
| `limits`, `check` | Обмеження інтерпретації та результат перевірки запису |
| `start`, `end` | Межі поля у форматі `YYYY-MM-DD` або `YYYY-MM`, якщо відомий лише місяць |
| `period` | Ті самі дати у вигляді підпису для читача |
| `fieldwork_periods` | Масив окремих інтервалів поля. Для агрегату саме він визначає складові хвилі |
| `published` | Дата публікації, окремо від дат інтерв’ю; порожня, якщо не встановлена |
| `date_precision` | `day` — день; `month` — місяць; `mixed` — різна точність складових |
| `date_kind` | `single_wave` — один інтервал; `aggregate` — кілька інтервалів |
| `date_status` | Статус підтвердження дат; значення пояснені нижче |
| `date_note` | Підстава датування та невизначеність чи суперечності |
| `date_source`, `date_source_url`, `date_source_location` | ID, URL та місце у джерелі, яке підтверджує дати |
| `date_checked_on` | Дата звірки метаданих, не оцінка якості дослідження |
| `source`, `source_url` | Основна публікація: ID та URL |
| `report` | ID повного звіту, якщо є; URL береться з `research.json → sources` |

Статуси дат: `reported_day` / `reported_month` — опубліковані дні / місяці; `retrospective_day` — дні названі в пізнішому релізі; `wave_dates_unresolved` — окремі дати потрібної хвилі не встановлені; `partial_aggregate` — неповні дати складових агрегату; `source_conflict` — джерело суперечливе; `corrected_retrospective_label` — підпис ретроспективи виправлено за первинним звітом.

**Приклад:** P35, Gallup 2024, поєднує 13–29 серпня та жовтень, для якого точні дні невідомі. `start` і `end` тут лише зовнішні межі для фільтрації: опитування не тривало безперервно між ними. Для P107 кінцевий день розходиться між паспортом та обкладинкою; це описано у `date_note`. [Журнал перевірки дат](../docs/DATA-AUDIT-2026-10-06.md).

## questions.csv — питання та формулювання

Один запис прив’язаний до опитування через `poll`. Він може містити одне питання або кілька пов’язаних тверджень чи умов експерименту. Тому 143 записи — не 143 незалежні вибірки і не обов’язково 143 окремі пункти анкети.

| Колонки | Зміст |
|---|---|
| `id`, `poll` | ID питання / запису та ID опитування у `polls.csv` |
| `wording_question` | Формулювання питання або твердження з джерела |
| `wording_prompt`, `wording_prompt_items` | Сценарій / умови; окремий список пунктів, якщо він є |
| `wording_options` | Опубліковані варіанти відповідей як JSON-масив |
| `wording_instructions` | Опубліковані інструкції інтерв’юеру, зокрема що не зачитувати |
| `wording_statements`, `wording_followups` | Твердження батареї та додаткові питання; не опції спільної шкали |
| `wording_experiment_dimensions` | Виміри та рівні експериментального сценарію |
| `wording_partial_options`, `wording_source_excerpt` | Доступна частина опцій або фрагмент джерела, коли повного тексту немає |
| `wording_basis` | Підстава відтворення; значення пояснені нижче |
| `wording_note`, `wording_language` | Обмеження відтворення й мова опублікованого тексту |
| `wording_source_url`, `wording_location` | Джерело формулювання та сторінка / розділ |
| `wording_question_source_url` | Додаткове джерело саме тексту питання, якщо відрізняється від основного джерела формулювання |
| `wording_reviewed_on` | Дата перевірки формулювання |
| `dimension` | Тематична категорія: переговори, поступки, очікування тощо |
| `base`, `limit` | База відповідей та межі інтерпретації |
| `scenario_summary`, `result_summary` | Редакційні перекази змісту й результату; не цитати з анкети |
| `source`, `source_url`, `location` | Джерело результату: ID, URL, сторінка / графік |
| `cluster` | Рання аналітична примітка про можливий перетин позицій. Не встановлений кластер і не належність респондента до групи; у чинній типології на сайті не використовується |

`wording_basis` розрізняє: `questionnaire` — анкету; `report` — текст звіту; `retrospective` — ретроспективний графік / таблицю; `publication-language` — текст мовою публікації, без підтвердження мови інтерв’ю; `reference` — довідкове формулювання іншої хвилі; `unavailable` — повне формулювання недоступне. Ретроспектива чи довідкова хвиля не підтверджує дослівність історичної анкети.

У 135 записах заповнено `wording_question`. Для Q109–Q111 (PONARS / WDLS) повні питання й шкали у відкритих матеріалах не знайдені: поле порожнє, доступні фрагменти відокремлено. **Приклад читання:** Q02 належить P01; потрібно читати разом `wording_question`, `wording_prompt` і `wording_options`, бо загальна шкала без конкретної умови не передає змісту питання.

## dynamics.csv — часові ряди

Один рядок — одна категорія відповіді в одній хвилі конкретної серії. Сукупність рядків із однаковими `series` і `poll` утворює розподіл цієї хвилі або його опубліковану частину. Таблиця містить 23 часові серії, а не всі результати всіх 143 записів каталогу.

| Колонки | Зміст |
|---|---|
| `poll` | ID опитування; точні дати, метод і вибірка — у `polls.csv` |
| `series` | Стабільний ID часового ряду, наприклад `KIIS_TERRITORY_GENERAL` |
| `period` | Підпис хвилі в числовому реєстрі, часто назва місяця; не заміна перевірених дат поля |
| `sort` | Ключ для сортування й розміщення точки на осі часу. Місяць або рік не означає встановленого дня інтерв’ю |
| `answer` | Короткий ключ категорії. Він може бути переказом або агрегатом кількох опцій |
| `pct` | Частка від 0 до 1 |
| `source`, `source_url`, `location` | Джерело числа та його місце |
| `note` | Зміни методики, агрегування та інші обмеження |

**Приклад:** P18, `KIIS_TERRITORY_GENERAL`, категорія «Допускають певні територіальні поступки», `pct=0.1` — це 10% у травневій хвилі 2022 року. Дослівну опцію потрібно брати зі зв’язаного формулювання, а не цитувати ключ `answer` як анкету.

Не додавайте різні хвилі або незалежні твердження в один розподіл. Сума показаних категорій не завжди дорівнює 100%: причиною можуть бути округлення, пропущені категорії або кілька відповідей. Зміни формулювань описані у примітках; сама лінія на графіку не гарантує повної зіставності.

## crosses.csv — перетини та підгрупи

Один рядок — опублікована частка певної відповіді в названій підгрупі. Тут є перетини двох позицій, демографічні зрізи та додаткові питання лише частині респондентів. Це не мікродані й не готова кластеризація. Розділ перетинів прибрано з інтерфейсу сайту; вихідна таблиця збережена.

| Колонки | Зміст |
|---|---|
| `poll` | ID опитування |
| `group` | Підгрупа, серед якої обчислено частку |
| `question`, `answer` | Короткі назви питання й відповіді; дослівність анкети цими полями не гарантована |
| `pct` | Частка від 0 до 1 у відповідній базі |
| `base` | Знаменник: кого вважають за 100%; n підгрупи або інші уточнення, якщо доступні |
| `source`, `source_url`, `location` | Джерело перетину та його місце |
| `note` | Умови читання: множинні відповіді, невідомий знаменник, округлення тощо |

**Приклад:** у P27 `pct=0.73` для закритих кордонів із РФ у групі «Допускають певні територіальні поступки» означає 73% **цієї підгрупи**, а не всіх опитаних. Без підтвердженого знаменника не можна механічно перемножувати це число з часткою прихильників поступок. Відсотки з різних опитувань не встановлюють, як ті самі люди поєднують відповіді.

## JSON-файли та зв’язки між таблицями

**`research.json`** містить масиви `polls`, `questions`, `dynamics`, `crosses` і довідник `sources` із парами `id` / `url`. `as_of` — дата зрізу добірки; дати перевірки окремих полів можуть бути пізнішими. `watchlist` — організації для відстеження, `coverage` — журнал охоплення джерел. `groups` — ранні робочі гіпотези, збережені в реєстрі; це не оцінені частки кластерів і не чинний розділ сайту. Розділ `questions` у цьому JSON містить короткий реєстр; повні тексти до CSV приєднуються з `wording.json`.

**`wording.json`** зберігає об’єкти у `items`. Масив `question_ids` пов’язує об’єкт із `questions.csv → id`; `series` і масив `polls` визначають відповідні хвилі часового ряду. Один текст може стосуватися кількох записів. Поле `mapping` зіставляє короткі ключі `answer` з індексами опцій, їх сумами або опублікованими категоріями; індекси починаються з нуля. Правила відтворення підписів реалізовано у [wording.js](../wording.js).

**`more-charts.json`** містить об’єкт `questions`, ключами якого є ID запитань. У кожному записі є `plots`: заголовок `heading`, примітка `caption`, одиниця `unit`, джерело `source_url` / `location` та масив `rows` із `label` / `value`. `percent` означає відсотки 0–100, `mean5` і `mean10` — середні на шкалах 1–5 та 1–10. Це також місце числових даних для окремих питань, які не входять до часових рядів. Масиви `series` і `wording` містять додаткові налаштування 11 серій і формулювання для їх відображення.

Для об’єднання даних:

1. Приєднуйте паспорт за `poll = polls.id` до питань, динаміки або перетинів. Зберігайте ID як текст: `Q01` і `Q026` не мають однакової кількості цифр.
2. Для формулювання конкретного ряду знайдіть у `wording.json → items` збіг `series` і наявність `poll` у масиві `polls`; застосуйте `mapping` до `answer`.
3. Для графіка окремого питання використайте його `id` як ключ у `more-charts.json → questions`; текст є в `questions.csv`.
4. Не з’єднуйте всі питання з усіма числовими рядками лише за `poll`: одна хвиля може містити кілька питань, і таке з’єднання створить хибні пари та дублікати. У `crosses.csv` немає окремого ID питання — відповідність потрібно перевіряти за змістом і джерелом.

Завантажувані на сайті CSV окремих графіків містять додатково приєднані формулювання й метадані; їхній набір колонок відрізняється від загальних таблиць цієї папки. Порядок відтворення файлів описано у [методології](../docs/METHODOLOGY.md#дані-й-відтворення).
